# MySQL 基础面试题集锦

本文档汇总了 DBA 入门及初中级面试中常见的 MySQL 基础问题，涵盖架构、引擎、索引、事务、锁、日志等核心领域。

---

## 一、MySQL 核心概念与架构认知

### Q1: 请简述 MySQL 的逻辑架构。
MySQL 的逻辑架构通常分为三层：
1.  **连接层 (Connection Layer)**：处理客户端连接、授权认证、安全校验等。
2.  **服务层 (Server Layer)**：核心层。
    *   **SQL 接口**：接收 SQL，返回结果。
    *   **解析器 (Parser)**：词法分析、语法分析，生成解析树。
    *   **优化器 (Optimizer)**：生成执行计划，选择索引。
    *   **查询缓存 (Query Cache)**：(MySQL 8.0 已移除) 缓存 Select 结果。
    *   **内置函数**：日期、时间、数学、加密函数等。
    *   所有跨存储引擎的功能（存储过程、触发器、视图）都在这一层实现。
3.  **存储引擎层 (Storage Engine Layer)**：负责数据的存储和提取。是插件式的，最常用的是 InnoDB 和 MyISAM。

### Q2: SQL 语句的执行顺序是怎样的？
编写顺序：`SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY ... LIMIT ...`
执行顺序：
1.  `FROM` <表名>：选取表，生成笛卡尔积。
2.  `ON` <筛选条件>：对笛卡尔积生成虚拟表。
3.  `JOIN` <join, left join, right join...>：添加关联表数据。
4.  `WHERE` <where条件>：对数据进行过滤。
5.  `GROUP BY` <分组字段>：分组。
6.  `HAVING` <分组筛选>：对分组后的结果过滤。
7.  `SELECT` <字段>：选取需要的字段。
8.  `DISTINCT`：去重。
9.  `ORDER BY` <排序字段>：排序。
10. `LIMIT` <行数>：分页。

## 二、存储引擎原理与选型

### Q3: MyISAM 和 InnoDB 的主要区别是什么？(必问)
| 特性 | InnoDB | MyISAM |
| :--- | :--- | :--- |
| **事务支持** | **支持 (ACID)** | 不支持 |
| **锁粒度** | **行级锁** (支持高并发) | 表级锁 (并发差，写锁阻塞读) |
| **外键** | 支持 | 不支持 |
| **崩溃恢复** | **支持 (Redo Log)** | 不支持 (断电可能丢数据/表损坏) |
| **MVCC** | 支持 | 不支持 |
| **索引结构** | 聚簇索引 (数据即索引) | 非聚簇索引 (索引指向数据地址) |
| **Count(*)** | 需扫描全表 (慢) | 内部维护计数器 (快，但在带 WHERE 时也慢) |
| **适用场景** | 核心业务、高并发、交易系统 | 读多写少、日志归档、全文本搜索(早期) |

### Q4: 什么是 Memory 引擎？
数据全部存储在**内存**中，读写速度极快，但**断电即失**。
*   默认使用 Hash 索引（等值查询快，范围查询慢）。
*   主要用于临时表或缓存极高频访问且不重要的数据。

## 三、SQL 基础与分类

### Q5: SQL 语言分为哪几类？
1.  **DDL (Data Definition Language)**：数据定义语言。`CREATE`, `DROP`, `ALTER`, `TRUNCATE`。
2.  **DML (Data Manipulation Language)**：数据操作语言。`INSERT`, `UPDATE`, `DELETE`。
3.  **DQL (Data Query Language)**：数据查询语言。`SELECT`。
4.  **DCL (Data Control Language)**：数据控制语言。`GRANT`, `REVOKE`。
5.  **TCL (Transaction Control Language)**：事务控制语言。`COMMIT`, `ROLLBACK`, `SAVEPOINT`。

### Q6: CHAR 和 VARCHAR 的区别？
*   **CHAR**：**定长**字符串。
    *   存取速度快（无碎片）。
    *   若内容长度不够，用空格填充（浪费空间）。
    *   适合存储长度固定的数据（如 MD5、身份证、手机号）。
*   **VARCHAR**：**变长**字符串。
    *   节省空间。
    *   需要额外 1-2 字节记录长度。
    *   适合存储长度不定的数据（如姓名、地址）。

### Q7: DELETE, TRUNCATE, DROP 的区别？
*   **DELETE** (DML)：逐行删除，支持 `WHERE`，**可回滚**，不重置自增 ID。
*   **TRUNCATE** (DDL)：清空整表，不支持 `WHERE`，**不可回滚**，重置自增 ID，效率高（直接丢弃数据页）。
*   **DROP** (DDL)：删除整张表（结构+数据），**不可回滚**。

## 四、索引原理与优化

### Q8: 为什么 MySQL 使用 B+ 树作为索引结构？
1.  **相比二叉树/平衡二叉树**：B+ 树层高更低（通常 3-4 层），磁盘 I/O 次数更少。
2.  **相比 B 树**：
    *   B+ 树非叶子节点只存索引不存数据，能容纳更多索引键，进一步降低层高。
    *   B+ 树叶子节点包含所有数据，且通过双向链表连接，**支持高效的范围查询**。

### Q9: 什么是聚簇索引与非聚簇索引？
*   **聚簇索引 (Clustered Index)**：
    *   索引结构和数据一起存放，叶子节点存储**完整的行数据**。
    *   InnoDB 的主键索引就是聚簇索引。
*   **非聚簇索引 (Secondary Index / 辅助索引)**：
    *   叶子节点存储的是**索引列的值 + 主键 ID**。
    *   查询时若需要非索引列，需先拿到主键 ID，再去聚簇索引查完整数据，这个过程叫**回表**。

### Q10: 什么是覆盖索引？
查询的列**全部**包含在使用的索引中，**无需回表**，直接从索引树返回结果。
*   例如：索引 `idx_name_age(name, age)`，执行 `SELECT name, age FROM user WHERE name='Alice'`。

## 五、事务原理与 ACID 特性

### Q11: 什么是 ACID？
*   **A (Atomicity) 原子性**：事务是不可分割的最小单位，要么全做，要么全不做。由 **Undo Log** 保证。
*   **C (Consistency) 一致性**：事务执行前后，数据保持逻辑一致（守恒）。由代码逻辑层面和数据库约束共同保证。
*   **I (Isolation) 隔离性**：并发事务之间互不干扰。由 **锁** 和 **MVCC** 保证。
*   **D (Durability) 持久性**：事务提交后，修改永久生效，断电不丢失。由 **Redo Log** 保证。

### Q12: 并发事务会带来哪些问题？隔离级别有哪些？
**并发问题**：
1.  **脏读 (Dirty Read)**：读到了未提交的数据。
2.  **不可重复读 (Non-repeatable Read)**：同一事务内两次读同一行，结果不同（被别人 Update/Delete 了）。
3.  **幻读 (Phantom Read)**：同一事务内两次读范围，结果行数不同（被别人 Insert 了）。

**隔离级别**：
1.  **Read Uncommitted (读未提交)**：发生脏读。
2.  **Read Committed (读已提交 RC)**：解决脏读。Oracle/PG 默认。
3.  **Repeatable Read (可重复读 RR)**：解决脏读、不可重复读。**MySQL InnoDB 默认**。通过 MVCC+Next-Key Lock 解决幻读。
4.  **Serializable (串行化)**：解决所有问题，但效率最低。

## 六、锁机制与并发控制

### Q13: MySQL 的锁粒度有哪些？
*   **全局锁**：`Flush tables with read lock`，整个库只读。常用于全库逻辑备份。
*   **表级锁**：MyISAM 默认。开销小，加锁快，不出现死锁；锁粒度大，并发低。
*   **行级锁**：InnoDB 默认。开销大，加锁慢，会出现死锁；锁粒度小，并发高。

### Q14: 什么是乐观锁和悲观锁？
*   **悲观锁**：认为冲突大概率发生。操作数据前先加锁（如 `SELECT ... FOR UPDATE`）。
*   **乐观锁**：认为冲突小概率发生。不加锁，提交时通过版本号 (`version`) 或时间戳检查数据是否被修改。

## 七、日志系统 (Redo/Undo/Binlog)

### Q15: MySQL 三大日志的区别？
1.  **Redo Log (重做日志)**：
    *   **层级**：InnoDB 引擎层。
    *   **作用**：保证**持久性** (Crash-safe)。记录物理日志（"在第 X 页第 Y 偏移量做了 Z 修改"）。
    *   **特点**：循环写，固定大小。
2.  **Undo Log (回滚日志)**：
    *   **层级**：InnoDB 引擎层。
    *   **作用**：保证**原子性**和 **MVCC**。记录逻辑日志（反向操作）。
3.  **Binlog (归档日志)**：
    *   **层级**：Server 层。
    *   **作用**：主从复制、数据恢复。
    *   **特点**：追加写，不覆盖。

### Q16: Binlog 的三种格式？
*   **Statement**：记录 SQL 语句。省空间，但可能导致主从不一致（如 `now()`, `uuid()`）。
*   **Row**：记录每一行数据的变更。空间占用大，但保证主从绝对一致。**推荐使用**。
*   **Mixed**：混合模式。

## 八、MySQL 性能优化基础

### Q17: 如何定位慢查询？
1.  开启 `slow_query_log`。
2.  设置 `long_query_time` 阈值（如 1s）。
3.  使用 `mysqldumpslow` 或 `pt-query-digest` 分析日志。

### Q18: Explain 执行计划主要看哪些字段？
*   **type**：访问类型。`system > const > eq_ref > ref > range > index > ALL`。优化目标至少 `range`。
*   **key**：实际用到的索引。
*   **rows**：预计扫描行数。
*   **Extra**：
    *   `Using index`：好（覆盖索引）。
    *   `Using filesort`：差（需文件排序）。
    *   `Using temporary`：极差（需临时表）。

### Q19: 最左前缀原则是什么？
联合索引 `(a, b, c)`，查询条件必须从最左边 `a` 开始匹配。
*   `a=1 and b=2` -> 走索引。
*   `a=1 and c=3` -> `a` 走索引，`c` 不走。
*   `b=2 and c=3` -> 不走索引。

## 九、数据库设计与规范

### Q20: 什么是数据库三大范式？
*   **1NF**：字段不可再分（原子性）。
*   **2NF**：在 1NF 基础上，非主键列完全依赖于主键（消除部分依赖）。
*   **3NF**：在 2NF 基础上，非主键列不依赖于其他非主键列（消除传递依赖）。

### Q21: 为什么要反范式设计？
范式越高，表拆分越细，Join 越多，性能越差。
为了性能，常**冗余字段**（以空间换时间），避免关联查询。例如在订单表冗余用户姓名。

## 十、MySQL 日常运维基础

### Q22: MySQL 主从复制原理？
1.  Master 将变更写入 **Binlog**。
2.  Master 的 Dump 线程将 Binlog 发送给 Slave。
3.  Slave 的 **I/O 线程**接收 Binlog 并写入本地 **Relay Log** (中继日志)。
4.  Slave 的 **SQL 线程**读取 Relay Log 并重放 SQL，将变更应用到数据。

### Q23: 数据库备份方式有哪些？
*   **逻辑备份**：`mysqldump`, `mypumper`。导出 SQL 语句。适合数据量小（<50G），跨版本迁移。
*   **物理备份**：`Xtrabackup`。拷贝物理文件。速度快，适合大数据量。
